# P02-010.4 — Category-Aware Market Discovery

Purpose: fix source-pool concentration before Trending ranking.

## What changes
- Candidate retrieval expands to Polymarket 500 and Kalshi 1000 records per scheduled run.
- New `category_discovery.py` groups normalized markets using the existing deterministic classifier.
- Discovery selects up to 25 candidates per category before filling remaining source-pool capacity.
- Existing P02-010.3 Quality Guardrails still decide what can appear in Trending.
- No market is relabeled, no probability is changed, and no missing category is fabricated.
- Dashboard uses discovery-selected candidates when `category_discovery.json` is present.
- Execution remains disabled.

## Important limitation
This is category-aware discovery over the venue records returned by the existing adapters. If a venue endpoint itself does not expose a desired category in the retrieved pages, P02 correctly reports that absence. A future venue-specific search/tag endpoint can be added only when supported by that venue's API.
