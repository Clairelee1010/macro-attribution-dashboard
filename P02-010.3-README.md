# P02-010.3 — Prediction Quality Guardrails

This package is based on the uploaded latest repo.

## Root cause found
The current live source pool is skewed before classification:
- Polymarket JSON in the uploaded repo: 100/100 records classify as Politics.
- Kalshi JSON: 132 Sports + 368 Other; the sampled Kalshi records have no usable positive probability/activity for Trending.
So the missing Technology / Equities / Crypto / Macro / Energy / Metals topics are primarily a **source discovery / sampling problem**, not only a classifier problem.

The uploaded `dashboard_payload.json` already classifies Pete Hegseth as Politics and the visible Kenneth-style parlays as Sports/Other. This confirms the classifier is working in the generated payload; screenshots can lag behind generated data/deployment.

## P02-010.3 changes
- Excludes unreadable multi-leg/parlay titles from the human-facing Trending list.
- Excludes probability 0/1 and no-activity/no-liquidity records from Trending.
- Removes forced fill. If only 5 good topics pass, the UI shows 5 — it does not manufacture 20.
- Preserves per-category cap = 5.
- Keeps raw venue datasets unchanged.
- Ranking label becomes `DETERMINISTIC_RELEVANCE_V3_QUALITY_GATED`.
- Dashboard wording becomes “Up to 20 / 最多 20 筆”.
- Does not alter Event Matcher, Discrepancy Engine, Trust/Security, P01 context, or execution boundary.
